# Rizo Lang Specification

Version 0.1 (draft) · Milestone 1: models

Rizo Lang is a secure, simple, full-stack web language. Source files end in `.rz`. The compiler, `rizolang`, turns Rizo Lang into existing technology: PostgreSQL for the database, TypeScript for the backend (Node.js) and, later, HTML and TypeScript for the frontend.

This document is the complete language reference. It is written for people and for AI models alike. If something is not described here, it is not part of the language.

> **Status:** Milestone 1 supports only `model` blocks. `api`, `page` and other blocks are planned but are **not** available yet. Using them is a compile error (RZ0211).

---

## 1. Design rules

1. **Dangerous mistakes are impossible, not just unlikely.** There is no raw SQL and no way to build a query from text.
2. **Strict and clear.** Every value has a static type. Every error says what went wrong, where and how to fix it.
3. **Small.** The whole language fits in this document.
4. **Secure by default.** Passwords are hashed automatically and can never be returned in an API response or logged. Inputs are validated automatically.

---

## 2. Files and basic syntax

- A source file is UTF-8 text with the extension `.rz`.
- A file contains zero or more `model` blocks. Nothing else is allowed at the top level.
- Comments start with `//` and run to the end of the line. There are no block comments.
- Whitespace (spaces, tabs, blank lines) separates tokens. Indentation has no meaning, but two spaces are conventional.
- **One field per line.** Fields are separated by new lines. There are no commas and no semicolons.
- Names contain only ASCII letters and digits and start with a letter. Underscores, hyphens and other characters are not allowed in names.
- Numbers are whole numbers, optionally negative: `100`, `0`, `-5`. Decimals (`1.5`) are not allowed.
- Lines and columns in error messages start at 1. A tab counts as one column.

---

## 3. Models

A model describes one kind of record stored in the database.

```rizo
model User {
  email: Email unique
  password: Password
  name: Text max 100
}
```

Rules:

- A model starts with the lowercase keyword `model`, then a name, then `{`. It ends with `}`.
- A model has at least one field.
- Every model automatically gets an `id: ID` field (a UUID generated by the database). **Do not declare `id` yourself.**
- Model names are unique within a file.
- A field is written `name: Type` followed by zero or more modifiers, all on one line.
- Field names are unique within a model.

---

## 4. Field types

There are exactly seven field types. Type names are case-sensitive and start with a capital letter.

| Type       | Meaning                                    | PostgreSQL    | TypeScript (stored) | Allowed modifiers              |
|------------|--------------------------------------------|---------------|---------------------|--------------------------------|
| `Text`     | Text. Length 0–10,000 by default.          | `TEXT`        | `string`            | unique, optional, min, max     |
| `Number`   | Whole number, −2147483648 to 2147483647.   | `INTEGER`     | `number`            | unique, optional, min, max     |
| `Bool`     | `true` or `false`.                         | `BOOLEAN`     | `boolean`           | optional                       |
| `Email`    | Email address, 3–254 chars, stored lowercase. | `TEXT`     | `string`            | unique, optional, min, max     |
| `Password` | Password. Stored only as a salted hash.    | `TEXT` (`<name>_hash`) | `PasswordHash` | optional, min, max         |
| `Date`     | Date and time, in UTC.                     | `TIMESTAMPTZ` | `Date`              | unique, optional               |
| `ID`       | A UUID, e.g. another record's id.          | `UUID`        | `string`            | unique, optional               |

Notes:

- `Number` is for whole numbers only. Store money as a whole number of cents.
- `Email` values must look like `name@domain.tld` and be lowercase. The database enforces both.
- `Password`:
  - The plain-text password is never stored. The column is named `<field>_hash`. For example, `password` is stored as `password_hash`.
  - Its `min` and `max` limit the plain-text length. The defaults are 8 and 128, and you can only tighten them.
  - It never appears in a public type (§7).
- `ID` fields hold a UUID. In Milestone 1, they are plain values. Links between models (foreign keys) come later.

---

## 5. Modifiers

Modifiers come after the type, on the same line, in any order. Each modifier may appear at most once per field.

| Modifier    | Meaning                                                                 |
|-------------|-------------------------------------------------------------------------|
| `unique`    | No two records may have the same value.                                 |
| `optional`  | The value may be missing (`null`). Without it, the field is required.   |
| `min N`     | Text, Email, Password: minimum length in characters. Number: minimum value. |
| `max N`     | Text, Email, Password: maximum length in characters. Number: maximum value. |

Limits and defaults:

| Type       | Default min | Default max | Allowed range for `min`/`max` |
|------------|-------------|-------------|-------------------------------|
| `Text`     | none        | 10000       | 0 to 1000000 (`max` ≥ 1)       |
| `Email`    | 3           | 254         | 3 to 254                      |
| `Password` | 8           | 128         | 8 to 128                      |
| `Number`   | none        | none        | −2147483648 to 2147483647     |

Rules:

- `min` must be less than or equal to `max`, after defaults are applied.
- `unique` is not allowed on `Bool` (only two values exist) or `Password` (hashes are salted).
- `min` and `max` are not allowed on `Bool`, `Date` or `ID`.

## 6. Naming

| Thing        | Style       | Examples                 | Becomes in PostgreSQL       |
|--------------|-------------|--------------------------|-----------------------------|
| Model name   | PascalCase  | `User`, `BlogPost`       | table `users`, `blog_posts` |
| Field name   | camelCase   | `email`, `firstName`     | column `email`, `first_name` |

- Table names are the snake_case model name in plural form: `+s`. Names ending in `s`, `x`, `z`, `ch` or `sh` take `+es`, and a consonant followed by `y` becomes `ies` (`Category` → `categories`).
- Reserved model names: the seven type names plus `PasswordHash`, `String`, `Boolean`, `Object`, `Array`, `Promise`, `Record`, `Error`, `Map`, `Set`, `Symbol`, `BigInt`, `Function`, `JSON`, `Math`, `Partial`, `Readonly`.
- Reserved field name: `id`.
- A field named `password`, `passwd`, `pwd`, `passcode` or `passphrase`, or whose name ends in `Password`, `Passwd`, `Passcode` or `Passphrase` (for example `adminPassword`), must have the type `Password`. This rule stops passwords from being stored as plain text by mistake.
- Two names must never produce the same table, column or TypeScript type name. For example, a `passwordHash` field next to a `password: Password` field is an error, because both would be stored as `password_hash`.
- Table and column names must be at most 63 characters long, which is PostgreSQL's limit.

## 7. What the compiler generates

`rizolang build app.rz` writes two files to `dist/`:

### 7.1 `dist/schema.sql` (PostgreSQL 13+)

```sql
CREATE TABLE "users" (
  "id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  "email" TEXT NOT NULL UNIQUE CHECK (char_length("email") BETWEEN 3 AND 254 AND "email" = lower("email") AND "email" ~ '^[^@[:space:]]+@[^@[:space:]]+[.][^@[:space:]]+$'),
  -- password: stored only as a salted hash, never as plain text
  "password_hash" TEXT NOT NULL,
  "name" TEXT NOT NULL CHECK (char_length("name") <= 100)
);
```

All identifiers are double-quoted. The whole schema runs inside one transaction.

### 7.2 `dist/types.ts`

For each model, three types are generated:

| Rizo Lang name  | TypeScript type | Use                                                         |
|-----------------|-----------------|-------------------------------------------------------------|
| `User`          | `User`          | The stored record. **Server-only.** Contains password hashes. |
| `User.public`   | `UserPublic`    | Safe to return from an API. **Never contains Password fields.** |
| `User.input`    | `UserInput`     | Data a client sends to create a record. Passwords are plain text here and are hashed before storage. `id` is not included. |

```ts
export interface User       { readonly id: string; readonly email: string; readonly password: PasswordHash; readonly name: string; }
export interface UserPublic { readonly id: string; readonly email: string; readonly name: string; }
export interface UserInput  { readonly email: string; readonly password: string; readonly name: string; }
```

- Optional fields have the type `T | null` in `User` and `UserPublic`, and are optional (`name?: T | null`) in `UserInput`.
- `PasswordHash` is a branded string, so a plain string cannot be assigned to it by accident.

## 8. Security guarantees

These guarantees are enforced by the compiler and covered by its test suite (`tests/security.test.ts`):

1. A `Password` field is never part of a `.public` type.
2. A `Password` is never stored in plain text. Its column always holds a hash.
3. Names can contain only letters and digits, and every identifier is quoted, so no name can inject SQL.
4. Unknown types, invalid modifiers and out-of-range limits are compile errors. When there is any error, no output is written.
5. Text has a maximum length by default, so no text column is unbounded.

## 9. Errors

Every error has a code, a location, a description and a fix:

```
app.rz:3:9 error RZ0301: Unknown field type "String" on field "User.name".
  3 |   name: String
    |         ^^^^^^
  fix: Use "Text" instead. Valid types: Text, Number, Bool, Email, Password, Date, ID.
```

- The first line is always `<file>:<line>:<column> error <code>: <message>`.
- The `fix:` line tells you exactly what to change.
- Syntax errors (RZ01xx, RZ02xx) stop at the first error. Checking errors (RZ03xx) are all reported together.
- The `rizolang` command exits with status 0 on success and 1 on any error.

| Code   | Meaning                                                     |
|--------|-------------------------------------------------------------|
| RZ0101 | Unexpected character (comma, semicolon, underscore, quote…) |
| RZ0102 | Invalid number (decimal, too large, letters attached)       |
| RZ0201 | Expected `model` at the top level                           |
| RZ0202 | Missing model name                                          |
| RZ0203 | Missing `{` after the model name                            |
| RZ0204 | Expected a field name or `}`                                |
| RZ0205 | Missing `:` after a field name                              |
| RZ0206 | Missing field type                                          |
| RZ0207 | Unknown modifier                                            |
| RZ0208 | Missing number after `min`/`max`                            |
| RZ0209 | Field does not start on a new line                          |
| RZ0210 | Model missing its closing `}`                               |
| RZ0211 | Block type not available yet (e.g. `api`)                   |
| RZ0212 | Unexpected token after a field type                         |
| RZ0301 | Unknown field type                                          |
| RZ0302 | Modifier not allowed on this type                           |
| RZ0303 | Modifier repeated                                           |
| RZ0304 | `min` greater than `max`                                    |
| RZ0305 | `min`/`max` value out of range                              |
| RZ0306 | Duplicate model name                                        |
| RZ0307 | Duplicate field name                                        |
| RZ0308 | Field named `id` (it is automatic)                          |
| RZ0309 | Model name not PascalCase                                   |
| RZ0310 | Field name not camelCase                                    |
| RZ0311 | Reserved model name                                         |
| RZ0312 | Two names map to the same table, column or TypeScript type  |
| RZ0313 | Model has no fields                                         |
| RZ0314 | Name too long for PostgreSQL                                |
| RZ0315 | Password-like field (e.g. `password`) not using `Password`  |
| RZ0901 | Cannot read the input file                                  |
| RZ0902 | Input file does not end in `.rz`                            |
| RZ0903 | Wrong command-line usage                                    |

## 10. Common mistakes

**Using types from other languages.** Valid types are `Text`, `Number`, `Bool`, `Email`, `Password`, `Date` and `ID`.

```rizo
// Wrong
name: String
age: Int
active: Boolean
createdAt: DateTime

// Right
name: Text
age: Number
active: Bool
createdAt: Date
```

**Commas, semicolons or several fields on one line.**

```rizo
// Wrong
email: Email, name: Text;

// Right
email: Email
name: Text
```

**Declaring `id`.** It is automatic.

```rizo
// Wrong
model User {
  id: ID
  email: Email
}

// Right
model User {
  email: Email
}
```

**Writing limits like function arguments or decorators.**

```rizo
// Wrong
name: Text(100)
email: Email @unique
nickname?: Text

// Right
name: Text max 100
email: Email unique
nickname: Text optional
```

**snake_case names.** Use camelCase for fields and PascalCase for models.

```rizo
// Wrong
model blog_post {
  first_name: Text
}

// Right
model BlogPost {
  firstName: Text
}
```

**Making a password unique, or weaker than 8 characters.**

```rizo
// Wrong
password: Password unique min 4

// Right
password: Password min 12
```

**Storing a password as `Text`.** Only `Password` is hashed and hidden from public types.

```rizo
// Wrong
password: Text

// Right
password: Password
```

**Decimal numbers.** Store money in cents.

```rizo
// Wrong
price: Number min 0.5

// Right
priceCents: Number min 50
```

## 11. Grammar

```ebnf
file      = { model } ;
model     = "model" NAME "{" { field } "}" ;
field     = NAME ":" TYPE { modifier } NEWLINE ;      (* one field per line *)
modifier  = "unique" | "optional" | "min" INT | "max" INT ;
TYPE      = "Text" | "Number" | "Bool" | "Email" | "Password" | "Date" | "ID" ;
NAME      = LETTER { LETTER | DIGIT } ;
INT       = [ "-" ] DIGIT { DIGIT } ;
LETTER    = "A".."Z" | "a".."z" ;
DIGIT     = "0".."9" ;
comment   = "//" { any character except newline } ;
```

The closing `}` of a model may be on the same line as its last field.

---

## 12. Planned (not available yet)

These are planned for later milestones. They are **not** part of the language yet, and using them is an error.

- `api` blocks with `requires login`, which return `Model.public` types.
- Queries through `db.Model` (always parameterized, never raw SQL).
- Links between models.
- Frontend `page` blocks.
